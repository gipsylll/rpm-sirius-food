# Практическая работа № 9 — Observability

## Что требовалось

Работа должна показать три столпа наблюдаемости распределённой системы:

- логи;
- метрики;
- трассировку.

Дополнительные уровни требуют Sentry и OpenTelemetry/Jaeger.

## Что реализовано

### Correlation ID

HTTP middleware в `app/core/observability.py`:

1. читает `X-Correlation-ID`;
2. проверяет его длину и печатаемость;
3. создаёт UUID, если заголовок не передан;
4. сохраняет значение в `ContextVar`;
5. возвращает его в response header;
6. добавляет его в JSON-логи и трассировку.

Пример:

```text
X-Correlation-ID: lab9-final-42
```

Один и тот же ID появляется в API, Outbox, publisher, кухне и доставке.

### Структурированные логи

Функция `log()` пишет JSON в stdout:

```json
{
  "event": "event_processed",
  "correlation_id": "lab9-final-42",
  "consumer": "kitchen",
  "order_id": 37,
  "duplicate": false
}
```

Основные события:

- `http_request`;
- `order_created`;
- `event_published`;
- `event_processed`;
- `event_rejected`;
- `publisher_retry`;
- `consumer_reconnect`.

### Prometheus

API публикует `/metrics`.

Собираются:

- `sirius_http_requests_total`;
- `sirius_http_request_duration_seconds`;
- стандартные process-метрики.

Prometheus также собирает метрики RabbitMQ через порт `15692`.

Конфигурация:

- `monitoring/prometheus.yml`;
- `monitoring/grafana/dashboards/sirius.json`.

Grafana показывает:

- HTTP RPS;
- p95 latency;
- количество сообщений RabbitMQ в очередях.

### OpenTelemetry и Jaeger

Код находится в `app/core/tracing.py`.

Трассировка включает:

- FastAPI HTTP spans;
- publisher span;
- kitchen consumer span;
- delivery consumer span;
- compensation consumer span.

Trace context сохраняется в Outbox и передаётся через RabbitMQ headers. `correlation_id` добавляется как атрибут span.

Сервисы Jaeger:

- `sirius-api`;
- `sirius-publisher`;
- `sirius-kitchen`;
- `sirius-delivery`;
- `sirius-compensation`.

## Sentry

Интеграция реализована в `app/core/tracing.py` и `app/main.py`:

- DSN читается из `SENTRY_DSN`;
- `correlation_id` записывается как Sentry tag;
- тестовый маршрут доступен при `SENTRY_TEST_ENABLED=1`:

```text
GET /__debug__/sentry
```

Реальная отправка события в Sentry требует DSN проекта. После добавления DSN можно выполнить готовый скрипт:

```bash
uv run --locked python scripts/verify_sentry.py
```

Скрипт сам пересоздаёт API с включённым тестовым endpoint, отправит ошибку и выключит endpoint после проверки. Это единственный внешний пункт, который нужно выполнить для полного уровня 9/10:

```bash
SENTRY_DSN=<DSN проекта Sentry>
SENTRY_TEST_ENABLED=1
docker compose up -d --force-recreate api
curl -H 'X-Correlation-ID: sentry-demo' \
  http://localhost:8000/__debug__/sentry
```

В Sentry нужно найти ошибку `Sirius Food Sentry test` и тег `correlation_id=sentry-demo`. После проверки выключить тестовый маршрут:

```bash
SENTRY_TEST_ENABLED=0
docker compose up -d --force-recreate api
```
