# ADR 001: промокоды, лояльность и трекинг заказа

## Решение

Промокод и списание баллов рассчитываются в одной транзакции заказа. Денежные значения хранятся в `NUMERIC(12,2)`, а промокод и счёт лояльности блокируются через `SELECT ... FOR UPDATE`. Уникальные ключи `PromoCodeUsage`, `PromoCompensation` и `LoyaltyTransaction` делают повторную доставку событий безопасной.

Начисление баллов выполняется отдельным consumer события `order.paid`: RabbitMQ остаётся транспортом бизнес-событий Saga. Отмена публикует `order.cancelled`; consumer возвращает списанные баллы, отзывает начисленные и восстанавливает лимит промокода.

Обновления статуса публикуются в Redis Pub/Sub `order_updates`. Каждая реплика API имеет локальный менеджер WebSocket и подписчик канала, поэтому клиент получает событие независимо от реплики, обработавшей PATCH. JWT в query-параметре выбран для совместимости с браузерным WebSocket API; токен короткоживущий и проверяется до принятия соединения.

## Последствия

Redis Pub/Sub не хранит историю, поэтому при переподключении сервер отправляет snapshot из PostgreSQL. Heartbeat `ping`/`pong` освобождает зависшие соединения. Celery Beat регулярно деактивирует истёкшие коды.
