# Защита лабораторной работы № 8

## Тема работы

**SSR-витрина «Сириус.Еда» на Next.js.**

Цель работы — сделать веб-витрину меню, которая получает блюда на сервере, отдаёт их в готовом HTML, поддерживает страницы отдельных блюд, 404, состояния загрузки и ошибки, а также обновляет данные через ISR.

## Короткий ответ для начала защиты

> В работе реализована витрина меню на Next.js 16 с App Router и TypeScript. Страница `/menu` и страницы `/menu/{id}` получают данные с REST API на сервере Next.js, поэтому названия и цены блюд уже находятся в исходном HTML. Для обновления данных используется ISR с периодом 60 секунд. Для несуществующего блюда вызывается `notFound()`, а ошибки API обрабатываются через `error.tsx`. Дополнительно реализована CSR-страница `/menu-csr`, где данные запрашиваются уже в браузере после запуска JavaScript.

## Что такое SSR, CSR и ISR

### SSR

**Server-Side Rendering** — сервер Next.js сам запрашивает данные у API и формирует HTML с блюдами до отправки страницы браузеру.

Преимущества для витрины:

- блюдо видно в исходном HTML;
- поисковая система может прочитать содержимое;
- пользователь получает готовый контент до выполнения клиентского JavaScript.

В проекте SSR используется для:

```text
/menu
/menu/{id}
```

### CSR

**Client-Side Rendering** — браузер сначала получает страницу, затем JavaScript выполняет `fetch` к API и добавляет блюда на экран.

В проекте CSR реализован на странице:

```text
/menu-csr
```

### ISR

**Incremental Static Regeneration** — Next.js кеширует результат серверного рендера и периодически обновляет его.

В проекте установлен период:

```typescript
export const revalidate = 60;
```

Это означает, что данные страницы могут обновляться примерно раз в 60 секунд. Первый запрос после истечения времени может получить старую страницу, пока Next.js обновляет её в фоне.

## Архитектура приложения

```text
Браузер
   |
   | GET /menu
   v
Next.js Server Component
   |
   | fetch с revalidate=60
   v
FastAPI REST API
   |
   v
PostgreSQL / Redis
```

Для CSR маршрут работает иначе:

```text
Браузер получает HTML без блюд
   |
   v
React useEffect()
   |
   v
fetch к NEXT_PUBLIC_API_URL
   |
   v
Блюда появляются после выполнения JavaScript
```

## Какие файлы показывать

### 1. Серверная страница списка блюд

Файл:

```text
sirius-food-frontend/src/app/menu/(list)/page.tsx
```

Группа `(list)` не попадает в URL, поэтому файл обслуживает маршрут `/menu`.

Показать:

```typescript
export const revalidate = 60;

export default async function MenuPage() {
  const items = await getMenuItems();
  ...
}
```

Что сказать:

> Это асинхронный Server Component. Он получает меню на сервере, передаёт блюда в `DishCard` и отдаёт пользователю уже сформированный HTML.

### 2. Server-side API-клиент

Файл:

```text
sirius-food-frontend/src/lib/api.ts
```

Здесь находятся:

- `API_URL` — адрес API для серверных запросов;
- `PUBLIC_API_URL` — адрес API для браузера;
- `getMenuItems()` — получение списка блюд;
- `getMenuItem(id)` — получение одного блюда;
- `formatPrice()` — форматирование цены в рубли.

Основной запрос выглядит так:

```typescript
fetch(`${API_URL}/menu/items`, {
  next: { revalidate: 60 },
});
```

Что сказать:

> Переменная `API_URL` используется сервером и не попадает в клиентский JavaScript. `next.revalidate` включает кеширование и периодическое обновление данных Next.js.

### 3. Страница отдельного блюда

Файл:

```text
sirius-food-frontend/src/app/menu/[id]/page.tsx
```

Показать:

```typescript
const item = await getMenuItem((await params).id);
if (!item) notFound();
```

Что сказать:

> Динамический сегмент `[id]` позволяет открывать страницу конкретного блюда. Если API не нашёл блюдо, вызывается `notFound()`, и Next.js возвращает страницу 404.

На странице также есть:

- название блюда;
- цена;
- категория;
- иллюстрация;
- кнопка добавления в корзину.

### 4. Клиентская страница CSR

Файл:

```text
sirius-food-frontend/src/app/menu-csr/page.tsx
```

Показать:

```typescript
"use client";
useEffect(() => {
  fetch(`${NEXT_PUBLIC_API_URL}/menu/items`)
    .then(...)
    .then(setItems);
}, []);
```

Что сказать:

> Эта страница является Client Component. Сначала показывается состояние загрузки, затем браузер запрашивает меню через `fetch`. Поэтому названий блюд нет в исходном HTML страницы.

### 5. Метаданные

Общие метаданные находятся в:

```text
sirius-food-frontend/src/app/layout.tsx
```

Там заданы:

- `metadataBase`;
- общий `title`;
- шаблон заголовка;
- общее описание сайта.

Метаданные конкретного блюда находятся в:

```text

```

Функция:

```typescript
generateMetadata()
```

создаёт индивидуальные `title`, `description` и `openGraph` для блюда.

Что сказать:

> Метаданные генерируются на сервере вместе со страницей. Поэтому конкретное блюдо имеет собственный заголовок и описание для поисковиков и социальных сетей.

### 6. Loading UI

Файл:

```text
sirius-food-frontend/src/app/menu/(list)/loading.tsx
```

Он автоматически используется Next.js во время загрузки маршрута `/menu` и показывает временное состояние:

```text
Загружаем меню...
```

Что сказать:

> `loading.tsx` позволяет показать пользователю понятное состояние загрузки, пока Server Component получает данные.

### 7. Обработка ошибок

Файлы:

```text
sirius-food-frontend/src/app/menu/error.tsx
sirius-food-frontend/src/app/menu/[id]/error.tsx
```

Оба файла являются Client Components и принимают функцию `reset`.

При ошибке показывается:

```text
Не удалось загрузить меню

```

или:

```text

```

Что сказать:

> Если API недоступен или серверная загрузка завершается ошибкой, Next.js показывает ближайший error boundary. Кнопка `reset` повторяет попытку загрузки.

## Как показать ISR

ISR лучше проверять в production-режиме:

```bash
npm run build
npm start
```

Сценарий демонстрации:

1. Открыть `/menu/2` и запомнить цену.
2. Изменить цену блюда через API.
3. Сразу обновить страницу — может остаться старая цена.
4. Подождать 60 секунд.
5. Обновить страницу и показать новую цену.

Что сказать:

> Страница не пересобирается вручную на каждый запрос. Next.js использует кеш и обновляет страницу после истечения `revalidate`.

Важно:

> Изменения могут появиться с задержкой также из-за Redis-кеша API. Первый запрос после истечения периода может получить старую версию, пока Next.js обновляет её в фоне.

## Сравнение SSR и CSR

| Критерий | SSR `/menu` | CSR `/menu-csr` |
|---|---|---|
| Где выполняется запрос | На сервере Next.js | В браузере |
| Блюда в исходном HTML | Да | Нет |
| Нужен JavaScript для первого контента | Нет | Да |
| Удобно для SEO | Да | Хуже |
| Подходит для интерактивных частей | Через Client Components | Да |

Если преподаватель спросит про скорость:

> Локальные замеры зависят от прогрева сервера, сети, кеша и устройства. Главное проверяемое отличие — SSR уже содержит блюда в HTML, а CSR получает их отдельным запросом после запуска JavaScript.

Зафиксированные локальные замеры из проекта:

| Время до появления блюда | SSR `/menu` | CSR `/menu-csr` |
|---|---:|---:|
| 1-й запуск | 65 мс | 47 мс |
| 2-й запуск | 22 мс | 25 мс |
| 3-й запуск | 21 мс | 37 мс |

Эти значения не являются универсальным сравнением производительности.

## Типовые вопросы преподавателя

### Почему использован SSR?

Публичное меню должно быть доступно поисковикам и пользователю ещё до выполнения JavaScript. SSR помещает данные блюд прямо в HTML.

### Чем SSR отличается от CSR?

При SSR запрос к API выполняет сервер Next.js. При CSR запрос выполняет браузер после загрузки JavaScript.

### Зачем нужен ISR?

Чтобы не запрашивать API и не строить страницу заново на каждый запрос, но при этом периодически обновлять меню.

### Зачем нужен `notFound()`?

Он сообщает Next.js, что блюдо отсутствует, и приводит к HTTP 404 и странице «Not Found».

### Зачем нужен `error.tsx`?

Чтобы обработать ошибку API на уровне конкретного маршрута и дать пользователю кнопку повторной попытки.

### Почему `AddToCartButton` — Client Component?

Кнопке нужны интерактивность и состояние React. Остальная страница может оставаться серверной.

### Почему в CSR используется `NEXT_PUBLIC_API_URL`?

Потому что запрос выполняется в браузере. Переменные без префикса `NEXT_PUBLIC_` доступны только серверу.

### Почему SSR лучше для SEO?

Поисковый робот может прочитать названия и описания блюд прямо из HTML, не дожидаясь выполнения JavaScript.

### Что произойдёт, если API недоступен?

Server Component выбросит ошибку, и Next.js покажет соответствующий `error.tsx`. На CSR-странице будет показано сообщение «Не удалось загрузить меню».

### Что проверяет `check.sh`?

Он проверяет ответы API, наличие блюд в SSR HTML, корректный 404 и отсутствие блюд в исходном HTML CSR.
