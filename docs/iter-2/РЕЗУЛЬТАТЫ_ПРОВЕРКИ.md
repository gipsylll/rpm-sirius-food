## 7. События и 9. Наблюдаемость

Создан заказ № 11 с `X-Correlation-ID: iter2-demo-42`. API записал заказ и событие `4bd18cc0-210e-45a1-8b44-3bcbe8688635`; publisher его отправил, кухня и доставка обработали с тем же correlation ID. В Jaeger trace `dbf08acd959c0818f1073098e3438abe` содержит span API, publisher, kitchen и delivery. В Prometheus оба источника (`sirius-api`, `rabbitmq`) были `up`; метрики очередей доступны. Повторная отправка того же события через RabbitMQ дала `duplicate: true` в обоих обработчиках; в БД сохранилось по одной записи кухни и доставки.

Позднее `uv run --locked python scripts/verify_lab7.py` успешно проверил на основном Docker Compose стеке с настоящими PostgreSQL и RabbitMQ: обычную доставку, дубликат, DLQ, Saga с однократным возвратом денег и Outbox при остановке и восстановлении брокера. Скрипт восстанавливает RabbitMQ и состояние курьеров; созданные тестовые записи остаются в основной базе.

Sentry: код интеграции и демонстрационная ошибка подготовлены, но реальная отправка и появление события с correlation ID в аккаунте не проверены: DSN не был предоставлен. Инструкция — в `ЗАПУСК_ЛАБ_7-10.md`.

## 8. SSR и CSR

`npm run build` прошёл при запущенном API. `./check.sh`: 7 PASS, 0 FAIL, включая названия блюд в HTML SSR, отсутствие данных в исходном HTML CSR и HTTP 404 для несуществующего блюда. В Chromium через Playwright, с отключённым браузерным кешем, три раза измерено время от начала навигации до появления блюда: SSR — 65, 22, 21 мс; CSR — 47, 25, 37 мс. DOMContentLoaded: SSR — 46, 7, 10 мс; CSR — 15, 12, 6 мс. Это локальный эксперимент с тёплым сервером и сетью без задержки; разница мала и не доказывает универсального преимущества по скорости. SSR содержит блюдо в исходном HTML, CSR запрашивает его после запуска JavaScript. Подробности доступны для повторения в браузере.

Дополнительно остановка API проверена в Chromium на `/menu/999999`: страница отобразила `Не удалось загрузить блюдо` и кнопку `Попробовать снова`; после запуска API основной стек восстановлен. Для этого динамического сегмента добавлен отдельный `src/app/menu/[id]/error.tsx`, а `generateMetadata` обрабатывает недоступность API отдельно.

## 10. Тестирование

`uv run --locked pytest -q`: 61 passed; в том числе Testcontainers с PostgreSQL и Pact. `uv lock --check` и `uv sync --locked` проходят. GitHub Actions настроен в `.github/workflows/tests.yml`, но запуск на GitHub и блокировка merge правилами защиты ветки не проверены: у локального репозитория нет remote.

### Мутационное тестирование

Область: `app/modules/orders/service.py`, выбранные тесты `tests/test_orders_service.py`, 158 мутаций. До новых тестов отмены: 46 убиты, 32 выжили, 80 не имели тестов. После добавления тестов отмены владельцем, сотрудником, чужим пользователем, повторной отмены и отсутствующего заказа: 96 убиты, 62 выжили, без непокрытых тестами мутаций. Рост выживших вызван тем, что ранее не покрытые 80 мутаций получили тесты и стали проверяться; тесты убили 50 из них. Из оставшихся выживших мутаций часть касается отправки уведомлений и текстов ошибок и требует отдельного анализа. Команда: `uv run --locked mutmut run`, результат: `uv run --locked mutmut results`.
