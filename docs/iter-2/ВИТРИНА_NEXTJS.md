# Витрина Next.js — работа № 8

> Этот файл перенесён из папки фронтенда. Команды ниже выполняются из `sirius-food-frontend/`. Исторические разделы шаблона содержат устаревшие TODO; фактическая проверка приведена в конце файла.

Next.js 16 (App Router) + TypeScript + Tailwind CSS + нативный fetch.
Кит даёт визуальные компоненты и REST-клиент; страницы-маршруты, состояния и
ISR вы пишете сами по методичке ЛР № 8.

## Быстрый старт

```bash
npm install
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000 — корень перенаправляет на /menu.
Бэкенд должен отвечать на адресе из .env.local (по умолчанию 127.0.0.1:8000).

Если ваш бэкенд на другом порту/хосте — поменяйте API_URL и
NEXT_PUBLIC_API_URL в .env.local и перезапустите dev-сервер. Код не трогаем.

## Проверка лабораторной работы № 8

Проверено на production-сборке с Next.js на `localhost:3002` и API на `localhost:8000`:

- `/menu` показывает меню; `/menu/1` — карточку с названием и ценой; несуществующее блюдо открывает страницу 404.
- `/menu-csr` загружает блюда в браузере. Для обращения браузера к API адрес `http://localhost:3002` добавлен в разрешённые CORS origins.
- У карточки блюда отображаются `title`, `description` и `og:title`.
- ISR: цена тестового блюда в API была изменена с 40 до 41 ₽. Сразу после изменения витрина показывала 40 ₽; после истечения периода и повторного запроса показала 41 ₽. Цена в API возвращена на 40 ₽. Следует учитывать, что после истечения срока первый запрос может вернуть старую страницу, пока Next.js обновляет её в фоне.

| Критерий | SSR `/menu` | CSR `/menu-csr` |
|---|---|---|
| Где запрашиваются данные | На сервере Next.js | В браузере после запуска JavaScript |
| Запрос к API в браузере | Нет | Да |
| Три браузерных замера | См. таблицу ниже | См. таблицу ниже |

SSR позволяет подготовить содержимое на сервере и подходит для публичной витрины, данные которой должны быть доступны поисковым системам. CSR подходит для интерактивных разделов, где данные нужны после запуска JavaScript. Время отображения зависит от сети, кеша и устройства; локальные измерения приведены ниже.

### Измерения SSR и CSR, 23.11.2026

Chromium через Playwright, локальный API и production Next.js, браузерный кеш отключён. Три последовательных открытия каждой страницы:

| Время от начала навигации | SSR `/menu` | CSR `/menu-csr` |
|---|---|---|
| DOMContentLoaded, мс | 46 / 7 / 10 | 15 / 12 / 6 |
| До появления блюда, мс | 65 / 22 / 21 | 47 / 25 / 37 |

В локальной сети результаты близки и зависят от прогрева; они не доказывают универсального преимущества одного подхода по скорости. SSR включает названия блюд в исходный HTML, а CSR загружает их в браузере после запуска JavaScript. Скрипт `./check.sh` показал 7 PASS, 0 FAIL.

При остановленном API динамический маршрут `/menu/999999` показывает `error.tsx` с сообщением «Не удалось загрузить блюдо» и кнопкой «Попробовать снова». После запуска API повторная попытка снова работает.
